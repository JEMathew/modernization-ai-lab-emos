## Objective and business value

Create one persisted, evidence-backed, explainable recommendation for every
assessed asset so a Mission Commander can challenge a 6R recommendation without
confusing it with an approved decision or execution authority.

## Scope

### Included

- Canonical six-strategy catalogue and Replace compatibility alias.
- Strict immutable recommendation, evidence-reference, and alternative models.
- Deterministic recommendation and alternative reasoning from existing results.
- Transactional assessment-run persistence and artifact projection.
- Synthetic application and Oracle data-platform reference journeys.
- Streamlit exposure and focused/full validation.

### Explicit exclusions

- Decision approval or DS-01 through DS-03 changes.
- Planning, execution, validation, outcomes, or learning stages.
- Mission Control prototype changes.
- Provider calls, production data, external systems, or infrastructure changes.

## Dependencies and readiness

- Predecessor slices: committed trusted assessment Slices 01 and 02; BASE-01.
- Required decisions/contracts: PRS-020 and ADR-0001.
- Existing behavior baseline: 146 Python tests passed on 2026-08-15.
- Data/configuration prerequisites: synthetic evidence registries only.

## Acceptance criteria

The acceptance criteria are PRS-020 Section “Acceptance criteria.” Failure is
explicit and safe, and the existing Apex happy path and DS-01 through DS-03
semantics remain unchanged.

## Validation plan

- Unit/contract: catalogue, aliases, models, deterministic selection, trust.
- Integration/BDD: persisted recommendation, application and data-platform runs.
- Browser/accessibility/responsive: Streamlit startup/health and relevant current
  presentation regression; no standalone prototype edits.
- Security: authority fail-closed test, secret scan, parameterized SQL review.
- Reliability: transaction rollback and deterministic replay.
- Performance: no new external call; bounded six-strategy evaluation per asset.
- Clean-checkout: not claimed without a commit and clean-checkout review.

## Risks and rollback

| Risk | Mitigation | Rollback signal/action |
|---|---|---|
| New record mistaken for approval | Literal recommendation status and no execution authority | Remove Phase A projection if prohibited state appears |
| Legacy Replace behavior changes | Normalize only in canonical record; retain DataFrame label | Revert canonical mapping while preserving old assessment |
| Persistence inconsistency | One existing transaction and artifact rollback | Disable recommendation inserts/projection |
| Dirty UI collision | Narrow insertion in existing assessment section | Revert only the Phase A hunk |
